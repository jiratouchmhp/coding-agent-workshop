# Agent Platform Observability, Audit Retention & Security Operations

Production reference for the **Observability** foundation of Gemini Enterprise Agent Platform: OpenTelemetry GenAI semantic conventions, multimodal GCS prompt-response capture and BigQuery analytics, ADK span hierarchy and Console dashboards, dual-attribution audit logging, tamper-evident WORM retention, SIEM export, emergency stop propagation windows, and Agent Anomaly Detection.

---

## 1. Mandatory OpenTelemetry GenAI Telemetry Prerequisites

Both **Offline Evaluation** and **Online Monitors** depend on OpenTelemetry Semantic Conventions for generative AI systems **v1.37.0+** (`https://opentelemetry.io/docs/specs/semconv/gen-ai/`).

### Required Google Cloud APIs

Enable these five APIs in your project (requires `roles/serviceusage.serviceUsageAdmin` or `roles/owner`):

```bash
gcloud services enable \
  aiplatform.googleapis.com \
  telemetry.googleapis.com \
  cloudtrace.googleapis.com \
  logging.googleapis.com \
  storage-component.googleapis.com \
  --project=PROJECT_ID
```

### Required OTel Spans & Events (Checked by Evaluation Services)

1. **Invoke agent span** attributes:
   - `gen_ai.agent.name` — Agent identifier.
   - `gen_ai.agent.description` — Brief description of agent purpose.
   - `gen_ai.conversation.id` — Unique session identifier.
2. **Inference events** (`gen_ai.client.inference.operation.details`):
   - `gen_ai.input.messages` — Prompts sent to the agent.
   - `gen_ai.output.messages` — Responses generated by the agent.
   - `gen_ai.system_instructions` — Underlying system instructions.
   - `gen_ai.tool.definitions` — Tool declaration metadata available to the agent.

### ADK Agent Runtime Telemetry Environment Variables

Configure OpenTelemetry tracing, logging, and GenAI semantic-convention capture via the three standard runtime environment variables:

```python
env_vars = {
    # Enables traces, logs, and GenAI metrics (ADK >= 2.6.0); omits prompt content by itself
    "GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY": "true",
    # Opts into OpenTelemetry GenAI v1.37.0+ semantic conventions
    "OTEL_SEMCONV_STABILITY_OPT_IN": "gen_ai_latest_experimental",
    # Captures prompts, responses, and user.id in Cloud Logging events (ADK Python enum ONLY)
    "OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT": "EVENT_ONLY",
}
```

- **May 22, 2026 `user.id` Cutoff:** Logging `user.id` when opting into prompt/response capture requires **ADK >= 2.1** effective May 22, 2026; agents opted in earlier must be redeployed and re-opted-in.
- **Console Telemetry Toggle:** Viewing or toggling **Observability** options under `Deployments -> Telemetry configuration -> Configure` requires Vertex AI SDK `>= 1.126.1`.
- **Native Model Armor Spans:** Model Armor automatically emits standardized OTel spans exposing real-time policy interceptions in traces with zero custom instrumentation.

## 2. Multimodal / Large Payload Recording in Cloud Storage & BigQuery Analytics

Agent Platform separates operational telemetry from sensitive conversational payloads:

- **Trace Spans:** Latency, status codes, span hierarchy, and structural attributes.
- **Cloud Storage (Recommended):** Full multimodal prompts/responses (audio, documents, images, plain/Markdown text, video; inline or GCS/public links) stored as JSONL without truncation, with fine-grained IAM and lifecycle/retention controls.
- **Cloud Logging (Fallback):** Basic text payloads only; subject to entry size limits.

The Agent Platform Console UI automatically stitches trace spans with GCS/Logging payloads in the Trace Details **Inputs/Outputs** tab (`Formatted` vs `Raw`, `Historical Messages` vs `Latest Messages`).

### Required Python Packages (Exact Pinned `fsspec`)

- **ADK Python:**
  ```text
  google-adk>=2.0.0
  opentelemetry-instrumentation-google-genai>=0.4b0
  fsspec[gcs]==2025.10.0
  ```
  Enable cloud export via `adk web --otel_to_cloud` or `get_fast_api_app(..., otel_to_cloud=True)`.
- **LangGraph ReAct:**
  ```text
  opentelemetry-instrumentation-vertexai>=2.2b0
  opentelemetry-instrumentation-google-genai>=0.4b0
  fsspec[gcs]==2025.10.0
  ```
  Also set `OTEL_PYTHON_LOGGING_AUTO_INSTRUMENTATION_ENABLED='true'`.

> **Pinning Warning:** Not all `fsspec` releases support OTel prompt/response GCS uploads; `fsspec[gcs]==2025.10.0` is the verified version.

### GCS Offloading Environment Variables

```bash
GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY='true'            # Required on Agent Runtime
OTEL_SEMCONV_STABILITY_OPT_IN='gen_ai_latest_experimental'
OTEL_INSTRUMENTATION_GENAI_UPLOAD_FORMAT='jsonl'
OTEL_INSTRUMENTATION_GENAI_COMPLETION_HOOK='upload'
OTEL_INSTRUMENTATION_GENAI_UPLOAD_BASE_PATH='gs://STORAGE_BUCKET_NAME/PATH'
# Recommended when uploading to GCS so raw message content is not duplicated on trace spans:
OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT='NO_CONTENT'
```

### Logs Explorer Reference Query

Every GCS upload writes a pointer entry to `projects/PROJECT_ID/logs/gen_ai.client.inference.operation.details` with labels `gen_ai.input.messages_ref`, `gen_ai.output.messages_ref`, and `gen_ai.system_instructions_ref` (e.g., `gs://my-bucket/<id>_input.jsonl`):

```text
logName="projects/PROJECT_ID/logs/gen_ai.client.inference.operation.details"
labels."event.name"="gen_ai.client.inference.operation.details"
```

In Cloud Trace Explorer (`https://console.cloud.google.com/traces/explorer`), filter by span name `generate_content` (or `gen_ai.operation.name: generate_content`) and click **Inputs/Outputs** on the span details pane.

### BigQuery Observability Analytics + BigLake External Table Join

Enable `bigquery.googleapis.com` and `bigqueryconnection.googleapis.com`, link your log bucket, and join `_AllLogs` with the JSONL objects in GCS:

```bash
# 1. Verify / enable Observability Analytics on log bucket (wait until lifecycleState == ACTIVE)
gcloud logging buckets describe LOG_BUCKET_ID --location=LOCATION
gcloud logging buckets update LOG_BUCKET_ID --location=LOCATION --enable-analytics --async

# 2. Create linked BigQuery dataset
gcloud logging links create LINKED_DATASET_NAME --bucket=LOG_BUCKET_ID --location=LOCATION
gcloud logging links list --bucket=LOG_BUCKET_ID --location=LOCATION

# 3. Create BigQuery Cloud Resource connection and grant its SA bucket read access
bq mk --connection --location=CONNECTION_LOCATION --project_id=PROJECT_ID \
  --connection_type=CLOUD_RESOURCE CONNECTION_ID
bq show --connection PROJECT_ID.CONNECTION_LOCATION.CONNECTION_ID
# Copy serviceAccountId (bqcx-...@gcp-sa-bigquery-condel.iam.gserviceaccount.com)
gcloud storage buckets add-iam-policy-binding gs://STORAGE_BUCKET \
  --member="serviceAccount:BQCX_SERVICE_ACCT_EMAIL" \
  --role="roles/storage.objectViewer"
```

Create the BigLake external table and join with completion logs using BigQuery pipe SQL:

```sql
CREATE OR REPLACE EXTERNAL TABLE `PROJECT_ID.EXT_TABLE_DATASET_NAME.EXT_TABLE_NAME` (
  parts ARRAY<
    STRUCT<
      type STRING,
      content STRING,
      mime_type STRING,
      uri STRING,
      data BYTES,
      id STRING,
      name STRING,
      arguments JSON,
      response JSON
    >
  >,
  role STRING,
  `index` INT64
)
WITH CONNECTION `PROJECT_ID.CONNECTION_LOCATION.CONNECTION_ID`
OPTIONS (
  format = 'NEWLINE_DELIMITED_JSON',
  uris = ['gs://STORAGE_BUCKET/PATH/*'],
  ignore_unknown_values = TRUE
);
```

```sql
FROM `PROJECT_ID.LINKED_DATASET_NAME._AllLogs`
|> WHERE
    log_name = 'projects/PROJECT_ID/logs/gen_ai.client.inference.operation.details'
    AND timestamp > TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 1 DAY)
    -- Optional single-trace filter: AND trace = 'projects/PROJECT_ID/traces/TRACE_ID'
|> SELECT
    insert_id, timestamp, labels, trace, span_id,
    STRING(labels['gen_ai.input.messages_ref']) AS messages_ref_uri
|> JOIN `PROJECT_ID.EXT_TABLE_DATASET_NAME.EXT_TABLE_NAME`
    ON messages_ref_uri = _FILE_NAME
|> RENAME `index` AS message_idx
|> CROSS JOIN UNNEST(parts) AS part WITH OFFSET AS part_idx
|> SELECT
    insert_id, timestamp, trace, span_id, role,
    part.content, part.uri, part.mime_type,
    TO_HEX(MD5(part.data)) AS data_md5_hex,
    part.id AS tool_id, part.name AS tool_name,
    part.arguments AS tool_args, part.response AS tool_response,
    message_idx, part_idx
|> ORDER BY timestamp, message_idx, part_idx
|> LIMIT 10;
```

You can chain BigQuery ML `AI.GENERATE(...)` (e.g., `gemini-2.5-flash-lite`) over joined rows with `OBJ.MAKE_REF(part.uri, ...)` to summarize or classify multimodal attachments directly in SQL.

## 3. ADK Span Hierarchy, Console Dashboards & `agents-cli` Telemetry Gotchas

### ADK OpenTelemetry Span Tree

```text
invoke_workflow (top-level run)
  └── invoke_agent (one per agent in the chain)
        ├── call_llm (model request)
        │     └── generate_content (underlying GenAI call from shared google-genai instrumentor)
        └── execute_tool (tool execution)
```

### Agent Platform Console Views

Navigate to `Agent Platform > Agent Registry` (`https://console.cloud.google.com/agent-platform/agent-registry/agents`) and select an agent:

- **`Observability` tab (6 subsections):**
  - **Overview:** Total sessions, average turns per session, invocations, input/output token series, traffic volume, p50/p95/p99 latency, and error rates.
  - **Evaluation:** Online Monitor time-series (response quality, safety, hallucination, tool use quality).
  - **Models:** Per-foundation-model p95 latency, call counts, error rates, quota failures, and token usage.
  - **Tools:** Per-tool p95 latency, call counts, error rates, and no-tool-called interaction frequency.
  - **Usage:** Runtime container CPU/memory allocation and token usage.
  - **Logs:** Filterable raw execution logs with severity, timestamps, and summaries.
- **`Traces` tab (3 views):**
  - **Session view:** Multi-turn conversation grouping; selecting a session opens a left panel of constituent traces plus aggregated messages, duration, tokens, and evaluation scores.
  - **Trace view:** Single end-to-end request DAG (left session panel hidden).
  - **Span view:** Individual operations (LLM call, API request, tool execution; left panel hidden).
- **`Topology` tab & MCP Servers:** Inbound/outbound agent dependency graph; MCP servers expose request count and p95 request duration.

### `agents-cli` Two Independent Content Tiers & Language Trap

For `agents-cli`-scaffolded projects, content capture is split across **two independent tiers**:

| Tier | Controls | Terraform Deploy Default | Key Gotcha |
|---|---|---|---|
| **GCS / BigQuery completions** | `OTEL_INSTRUMENTATION_GENAI_COMPLETION_HOOK=upload` + `LOGS_BUCKET_NAME` | **On** (full content; Python ADK & Claude only) | Does **NOT** honor `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT`. Drop the upload block in `service.tf` to disable. |
| **Trace spans / Logging events** | `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` (+ `ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false` in Python) | **Off** (`NO_CONTENT`) | **ADK Python** requires enum (`NO_CONTENT`, `EVENT_ONLY`, `SPAN_ONLY`, `SPAN_AND_EVENT`); `"true"`/`"false"` silently fall back to `NO_CONTENT`. **ADK Go** requires boolean (`"1"`/`"true"`); enum strings elide all content! |

### `agents-cli` Deployment Order Rule

- Run `agents-cli infra single-project --apply --project PROJECT_ID` **before** your first `agents-cli deploy` if you want Terraform-managed prompt-response logging or `--bq-analytics` (`BQ_ANALYTICS_DATASET_ID`).
- **Never apply Terraform after an imperative Agent Runtime deploy.** Either delete and recreate under Terraform, or keep the imperative instance and run:
  ```bash
  agents-cli deploy --update-env-vars "KEY=VALUE,..."
  ```
  Then manually grant the runtime SA: `roles/storage.admin` (or `roles/storage.objectCreator`), `roles/logging.logWriter`, `roles/cloudtrace.agent`, plus `roles/bigquery.dataOwner` and `roles/bigquery.jobUser` when using `--bq-analytics`.

## 4. Security Operations: Dual-Attribution, Emergency Stop, Latency, WORM & Anomaly Detection

### Dual-Attribution Audit Logging

When an agent acts on behalf of a human (user-delegated authority), Cloud Logging records **both** the SPIFFE-based agent identity (`principal://...` in audit logs, `spiffe://...` in execution logs) and the initiating user. Autonomous actions log directly to the agent identity. Isolate agentic events with:

```text
jsonPayload.is_agentic=true OR labels.is_agentic="true"
```

### Emergency Stop & Policy Propagation Latency

| Mechanism | Impact on Active Traffic & Sessions | Propagation Time |
|---|---|---|
| **Delete runtime** (`client.runtimes.delete(name=..., force=True)` / `remote_agent.delete(force=True)` / `reasoningEngines.delete`) | Terminates all containers, kills active `streamQuery` streams, and permanently invalidates SPIFFE identity. *(Manually remove defunct principal from UAP rules/bindings afterward.)* | **Immediate** once delete finishes (**seconds to a few minutes**). |
| **Traffic rollback / archive revisions** (`trafficSplitManual` 100% to known-good revision, or update `agent_gateway_config`) | Redirects 100% of root traffic without deleting agent/identity. Direct calls to a specific revision path continue until that revision is archived/deleted. | **Seconds to a few minutes**. |
| **Agent Gateway UAP `DENY`** (active enforcement: remove `iamEnforcementMode` from `metadata` via CLI/Terraform/REST — IAP rejects explicit values other than `"DRY_RUN"`; Console UI shows **Enforce policies**) | Blocks outbound tool/MCP/A2A calls while preserving containers for forensics. Does **not** kill already-open streaming connections unless re-authorized. | **Eventually consistent:** typically **~2 min**, up to **7+ min** globally (`principalSet`/group updates: **minutes to hours**). |
| **IAM deny / role revocation / PAB policy** | Blocks Google Cloud API calls on new requests; containers stay running. | **Eventually consistent:** typically **~2 min**, up to **7+ min** globally. |

**Incident Playbook Rule:** Never rely solely on UAP/IAM revocation during an active runaway tool loop — always pair policy revocation with **runtime deletion** or **`trafficSplitManual` rollback**, then verify containment by querying `is_agentic=true` and `networkservices.googleapis.com/gateway_requests` denials.

### Telemetry & Security Finding Latency Expectations

| Signal / Control | Ingestion / Evaluation Model | Typical Visibility Latency |
|---|---|---|
| **Cloud Audit Logs & Agent Gateway logs** (`cloudaudit.googleapis.com/*`, `networkservices.googleapis.com/gateway_requests`) | Synchronous generation, indexed into Cloud Logging. | **Seconds** *(Gotcha: `gcloud logging read --freshness=6h` can miss freshly indexed entries — use `--freshness=1d`.)* |
| **Runtime stdout/stderr** (`aiplatform.googleapis.com/reasoning_engine_stdout`, `reasoning_engine_stderr`) | Streamed asynchronously from runtime container. | **Seconds**. |
| **Cloud Trace spans** | Exported asynchronously on span completion (subject to `samplingRate` / `parentBasedSampling`). | **Seconds**. |
| **Cloud Monitoring metrics** | Periodic sampling from Runtime, Gateway, and evaluators. | Sampled every **60–120s**; visibility delay **180–420s**. |
| **Inline enforcement** (Agent Gateway, IAP, Model Armor) | Synchronous on live request path. | **0 ms post-processing delay** (real-time inline). |
| **Agent Anomaly Detection -> SCC** (`AGENT_SESSION_ANOMALY`, Preview) | Asynchronous out-of-band 3-layer pipeline (zero live latency). | Scope enablement **~40 min**; anomaly metrics sampled every **120s** (up to **420s** delay) + SCC sync latency. |

### Tamper-Evident WORM Audit Retention

- `_Required` bucket (Admin Activity / System Event): fixed **400-day** immutable retention.
- `_Default` bucket (`data_access`, `policy_denied`, `gateway_requests`, `is_agentic=true`): **30-day** default retention.
- **Custom Locked WORM Log Bucket (1–3,650 days — irreversible lock!):**
  ```bash
  gcloud logging buckets create agent-audit-worm-bucket \
      --location=LOCATION \
      --retention-days=RETENTION_DAYS \
      --project=PROJECT_ID

  # IRREVERSIBLE: prevents even project owners / org admins from deleting or shortening retention
  gcloud logging buckets update agent-audit-worm-bucket \
      --location=LOCATION \
      --locked \
      --project=PROJECT_ID
  ```
  Pair locked log buckets with a **project lien** (prevents deletion via project deletion) or export to GCS with **Bucket Lock**.

### Export Audit Logs to Google SecOps or Third-Party SIEM (Pub/Sub Sink)

```bash
# Replace --project=PROJECT_ID with --organization=ORG_ID --include-children for org-wide aggregated sink
gcloud logging sinks create agent-audit-siem-sink \
    pubsub.googleapis.com/projects/DESTINATION_PROJECT_ID/topics/TOPIC_ID \
    --log-filter='logName:("cloudaudit.googleapis.com" OR "networkservices.googleapis.com%2Fgateway_requests" OR "aiplatform.googleapis.com%2Freasoning_engine") OR jsonPayload.is_agentic=true OR labels.is_agentic="true"' \
    --project=PROJECT_ID

WRITER_IDENTITY=$(gcloud logging sinks describe agent-audit-siem-sink \
    --project=PROJECT_ID \
    --format='value(writerIdentity)')

gcloud pubsub topics add-iam-policy-binding TOPIC_ID \
    --project=DESTINATION_PROJECT_ID \
    --member="${WRITER_IDENTITY}" \
    --role="roles/pubsub.publisher"
```

### Agent Anomaly Detection (Preview / Allowlist)

Out-of-band behavioral security monitor that writes `AGENT_SESSION_ANOMALY` findings to Security Command Center (requires SCC Standard, Premium, or Enterprise tier) and Cloud Monitoring:

- **3-Layer Pipeline:** **Layer 1** (lightweight ML statistical down-sampling) -> **Layer 2** (reasoning-based session threat analysis & explanation) -> **Layer 3** (invocation-level tool/state/parameter deep dive).
- **Threat Coverage (OWASP Agentic Top 10):** Tool misuse (`ASI02`), Identity privilege abuse (`ASI03`), Agentic cascading failures (`ASI08`), Rogue agents (`ASI10`), and Resource exhaustion.
- **Eligibility Requirements (all required for agent discovery):**
  - Runtime: Agent Runtime, `CLOUD_RUN_SERVICE`, `GKE_WORKLOAD` (ADK Python `>= 2.1.0`), or `AGENT_TYPE_OTHER` on AWS/Azure (ADK Python `>= 2.12.0` + Workload Identity Federation + `telemetry.googleapis.com`).
  - Matching bucket region (`US` scope allows `us` or `global` `_Default`; `EU` scope requires `eu` logging bucket) + **Log Analytics & Observability Analytics enabled**.
  - OTel tracing/logging active (`GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY="true"` / `otel_to_cloud=True`), prompt/response content capture enabled, and active traffic flowing.
  - Supports automatic agent enrollment on regional `AgentAnomalyDetectionScope` or manual per-agent opt-in.

## 5. Verification & Troubleshooting

| Symptom | Root Cause | Verification / Fix |
|---|---|---|
| No traces in Cloud Trace or Agent Registry | Telemetry env var missing or SA lacks `roles/telemetry.tracesWriter` / `roles/cloudtrace.agent` | Check `GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true`, `otel_to_cloud=True` (ADK), and SA IAM roles. |
| Spans exist but **Inputs/Outputs** tab is empty or eval fails with missing content | `OTEL_SEMCONV_STABILITY_OPT_IN` missing, or `"true"` passed in ADK Python (falls back to `NO_CONTENT`), or Go passed `"EVENT_ONLY"` | Set `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` and Python=`EVENT_ONLY` (or GCS upload) / Go=`true`. |
| GCS prompt-response objects missing | `fsspec[gcs]` version mismatch or SA lacks `roles/storage.objectUser` on bucket | Pin `fsspec[gcs]==2025.10.0`; grant `roles/storage.objectUser` to the **agent SA** (not your user account); inspect logs for `labels."event.name"="gen_ai.client.inference.operation.details"`. |
| Audit log verification misses recent gateway/runtime event | Narrow CLI freshness window | Re-run `gcloud logging read` with `--freshness=1d` instead of `--freshness=6h`. |
| Agent missing from Agent Anomaly Detection monitored list | Bucket region mismatch (`EU` scope with `global` bucket), Log Analytics disabled, ADK `< 2.1.0` (`< 2.12.0` cross-cloud), or zero live traffic | Verify bucket region, enable Log Analytics, upgrade ADK, and send test traffic. |
